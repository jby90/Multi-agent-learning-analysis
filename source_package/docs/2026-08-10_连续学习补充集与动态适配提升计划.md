# 连续学习补充集与动态适配提升计划

## 1. 为什么正式结果是 180/260

冻结 50×2 中共有 260 个应记录的适配节点，其中 80 个节点的冻结金标准明确要求 `keep`。现行“动态有效调整率”只把难度、路径、任务复杂度或追问发生真实变化的成功节点计入分子，因此该集合理论最高值就是：

`(260 - 80) / 260 = 180 / 260 = 69.2308%`

这不是系统只有 69% 的节点判断正确，而是把“正确保持不变”放进分母、同时又禁止它进入分子造成的结构上限。不得通过改写冻结 50 例、把 `keep` 伪装成变化或放宽动作匹配来提高数字。

## 2. 独立补充集的定位

新增 `continuous_learning_supplement_v1`，与正式 50×2 隔离，只用于开发与消融：

- 10 个核心知识点；
- 3 类岗位画像；
- 每个知识点 4 类连续场景：能力回退、补学恢复、岗位迁移、稳定保持；
- 共 40 例；
- 60 个确实需要变化的节点；
- 10 个 `keep` 稳定性对照节点。

补充集不得写回正式五指标，也不得被生产运行时读取金标准字段。

## 3. 两个互补指标

### 3.1 连续适配召回率

`成功执行预期变化的节点数 / 金标准明确要求变化的节点数`

只统计确实需要变化的 60 个节点，目标不低于 85%。一个节点必须同时满足：

1. 调整依据来自真实历史和当前交互；
2. 动作属于允许集合；
3. 难度、路径、任务复杂度或追问至少一项真实变化；
4. TRACE 中存在 before/after、evidence_ids 和原因码。

### 3.2 稳定保持准确率

`正确执行keep的稳定对照节点 / 全部稳定对照节点`

目标不低于 90%。这样既考查系统会不会调整，也防止系统为“刷适配率”而无意义地频繁变化。

## 4. 学生实施顺序

1. 先运行补充集结构校验，不接生产系统。
2. 为学习画像增加跨会话历史前缀：已学知识点、最终难度、历史误区、最近练习时间、岗位职责变化。
3. 在 DiagnosisAgent 前增加只读的长期画像摘要，不修改现有 21 条状态转移。
4. 由确定性策略先判断 `change_required`；LLM 只能生成教学内容，不能决定是否需要变化。
5. 将历史误区和证据缺口交给创新 B 选靶；需要受控解释时继续使用创新 A 的 Review—辩护—再审核闭环。
6. 每完成一种场景，先跑固定桩与非 live 回归，再跑补充集；不得直接跑正式 50×2试错。
7. 补充集稳定后，重新完整运行正式 Seed A 和 Seed B，确认正式三指标和两个辅助 KPI 不回退。

## 5. 架构红线

- 不修改 21 条状态转移；
- 不放宽 R-01～R-06；
- 不移除证据绑定、Review、SQL 沙箱和 T17；
- 不把金标准注入生产路由；
- 不把 `keep` 改名后计作有效变化；
- 不把补充集结果包装为正式 50×2成绩；
- 不用 LLM 自由判断升降档，动作仍由确定性状态和证据门禁控制。

## 6. 运行命令

```powershell
cd source_package
python -m pytest -q eval/test_continuous_learning_supplement.py
python -m eval.continuous_learning_supplement --output-dir ../outputs/continuous_learning_supplement_v1
```

生成 JSON、CSV 和结构摘要后，学生可据此开发真实跨会话 runner。当前版本交付的是冻结补充集、校验器和开发门禁，不声称已经取得连续适配率成绩。
