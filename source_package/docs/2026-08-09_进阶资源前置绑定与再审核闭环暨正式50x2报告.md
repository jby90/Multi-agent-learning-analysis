三类进阶实操资源的前置知识绑定与 `approve_with_fix → 修订 → 再审核` 闭环已完成。修复后的冻结代码已分别完整运行 Seed A、Seed B 各 50 例；两轮均为生产路由、50/50 完成、0 失败。严格覆盖审计由修复前的缺口恢复为 `60/60` 覆盖格通过、`10/10` 核心知识点完整闭环通过。

本报告中的指标模式为 `AUTO_PRELIMINARY`，仅是机器自动初算，不是 `FINAL_HUMAN_REVIEWED` 最终成绩。事实内容单元、适配节点和覆盖格的人工字段均保持 `PENDING_HUMAN`。

## 2. 修复内容

### 2.1 三类进阶资源的前置知识绑定

进阶实操指南不再只写自然语言前置提示，而是绑定到已批准知识库元数据：

| 正式案例 | 进阶资源知识点 | 前置知识点 | 证据块 |
|---|---|---|---|
| E2E-013 | 完成率计算 | 责任单元定位 | KB-009 |
| E2E-038 | 异常衰减规律 | 三道工序与传导关系 | KB-001-B |
| E2E-043 | 责任单元定位 | 三道工序与传导关系 | KB-001-B |

系统同时执行三层约束：

1. Task Agent 在实操指南中显式展示“前置检查”；
2. Evidence Bundle 要求指南绑定与证据包中的前置知识完全一致；
3. Review Agent 按目标知识点、目标难度、前置知识点、`chunk_id`、学习目标和可见文本进行确定性核验。

伪造前置知识、错误 `chunk_id`、错误学习目标或只在结构化字段中声明但未在指南正文呈现，都会被拒绝。

### 2.2 `approve_with_fix` 再审核闭环

伴生资源审核不再把 `approve_with_fix` 当作最终通过：

1. Review 返回 `approve_with_fix`；
2. 系统生成新 artifact/version，并记录被修订消息、被修订 artifact、修订原因和规则 ID；
3. 修订稿重新进入 Review；
4. 只有精确 `approve` 才允许发布；
5. 超过原有审核预算仍未精确通过则 fail-closed。

该改动复用原有审核预算、消息总线、TRACE、A 选择性辩护和安全收尾，没有修改 21 条状态转移、R-01～R-06、B 误区选靶、T17、Text2SQL 或 SQL 沙箱。
