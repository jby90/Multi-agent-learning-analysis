# 资源闭环与覆盖门禁修复报告

## 1. 修复目标

本轮只修复正式 v3.2 TRACE 暴露的资源谱系与覆盖门禁缺口，不修改以下冻结内容：

- 21 条状态转移；
- R-01～R-06 审核规则；
- A：事务级选择性辩护；
- B：边际误区关联选靶；
- T17 降阶、Text2SQL、SQL 沙箱；
- 三项核心指标和两个辅助 KPI 的冻结定义。

旧 Seed A/B 的 60 个覆盖格审计结果为 `0/60`。路由、路由证据、学习契约、测验和反馈均可达，主要失败原因是：画像引用缺失、实操指南未生成或未审核，以及升档后只有测验而没有同档微课和实操指南。

## 2. 已完成修复

### 2.1 统一资源绑定边界

`EvidenceBundle.bind()` 现在统一校验并写入：

- `knowledge_point`；
- `difficulty`；
- `student_profile_ref`；
- `learning_contract_id`；
- `evidence_bundle_ref`；
- `lineage_id`；
- `artifact_id`；
- `generation_stage`。

跨知识点、跨难度、跨画像或跨契约的草稿会在进入 Review 前被拒绝。

### 2.2 补齐实操指南资源

Task Agent 新增答题安全的 `practice_guide` 投影。指南只给操作步骤和完成标准，不泄漏标准 SQL、标准答案或期望结果行。初始档微课、实操指南和测验仍并行生成。

### 2.3 新增被动审计通道

并行伴生资源使用 `passive_audit`：消息仍经过统一消息结构校验并追加到同一 TRACE，但不作为状态机输入。因此可以保留完整 Review、选择性辩护与再审核证据，同时不会误触发主状态转移。

### 2.4 补齐升档后的完整资源闭环

升档时不再复用初始档上下文，而是：

1. 创建不可变学习契约的新修订版；
2. 按目标难度创建新的 Evidence Bundle；
3. 生成并审核同档微课；
4. 生成并审核同档实操指南；
5. 沿原 T19→T09→T10 主链生成并审核分阶测验；
6. 将三类资源聚合为同契约、同证据包的 Resource Bundle。

没有新增状态，也没有改变原状态机语义。

## 4. 尚未声明完成的事项

旧 Seed A/B TRACE 是修复前证据，不能用于证明修复后的正式覆盖率。代码最终冻结并配置正式模型、只读数据库后，必须重新完整运行 Seed A 50 例和 Seed B 50 例，再生成 `AUTO_PRELIMINARY`。不得把本轮固定桩回归或旧 TRACE 标记为正式评测结果。

正式运行前还需：

1. 再次执行非 live 全量、真实路由、第二域和 A+B 门禁；
2. 固定代码哈希、Prompt、模型、温度、知识库与领域配置；
3. 独立运行 Seed A 与 Seed B；
4. 对新 60 个覆盖格重新执行缺口审计；
5. 若门禁全部通过，再生成自动初算工作簿；
6. 学生双人复核和仲裁完成后，才可生成 `FINAL_HUMAN_REVIEWED`。
