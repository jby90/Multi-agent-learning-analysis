## 三、当前已经修复了什么

### 3.1 诊断与真实路由

- 保留 5 题岗前测，每会话最多追加 2 道固定诊断探针；
- `DiagnosticRouter` 使用纯确定性规则生成 `knowledge_point_plan`；
- 正确答案不会被标记为盲区；
- 生产会话按计划选择首个待训练知识点，不再使用 `blind_spots[0]`；
- 正式评测不注入目标知识点、模板或答案；
- 10 个核心知识点均真实可达，永久不可达为 0。

### 3.2 个性化学习闭环

- 岗位画像、诊断证据和学习契约共同决定初始知识点与难度；
- 微课、实操指南、分阶测验按相同知识点、难度、画像、契约和证据包生成；
- 升档后会生成新的同档微课、实操指南和测验，不再只升测验难度；
- 每个资源都有 artifact/version/lineage，可追溯重写、辩护、再审核和发布。

### 3.3 多智能体并行协同与创新 A+B

- 主链保持有序状态机，局部资源生成与审核使用并行 DAG；
- R-02 事实证据审核、R-03 难度/岗位适配审核及其他规则可并发，最终确定性汇聚；
- 创新 A：按审核规则性质、事务内辩护历史和固定预算决定是否选择性辩护；
- 创新 B：只从真正通过 Review 的关系追问中选择边际误区目标；
- A+B 不改变确定性安全边界，不让多个 Agent 自由群聊或无限辩论。

### 3.4 追问、纠错与降阶

- 扩展了“不知道、不会、不清楚、无关文本、题目复述”等无效回答识别；
- 防止仅复述题目或粘贴题干被判定掌握；
- 新问题前会显示上一轮评价和继续/升档理由；
- 历史错误未纠正时，单题答对不能直接跳过纠正门禁；
- T17 能真正降档；basic 无法再降时更换内容；超过次数上限后标记 `deferred` 并进入下一知识点，避免无限循环。

### 3.5 实操与 SQL 安全

- SQL 只读沙箱、表和字段白名单保持不变；
- 非 SELECT、越权字段、语法错误和不开放字段会被阻断；
- 多次失败可以逐级给出定位提示、结构化提示和半填充框架；
- 轮询单次失败不会立即删除会话；
- 切换知识点时清理旧 SQL 草稿，避免上一题内容污染下一题。

### 3.6 前端与可解释性

- 学员界面、微课、实操和训练报告已重排；
- 协同视图支持 Agent 动效、审核小组和运行拓扑；
- 调试拓扑可查看节点状态、参数和日志，并按会话隔离；
- 学员模式可显示后台 Agent 当前任务、进度和完成情况；
- 查询结果和微课支持专注/最大化学习。

### 3.7 最新资源闭环修复

三类进阶资源已绑定真实前置知识：

| 资源 | 前置知识 | 证据 |
|---|---|---|
| 完成率计算·进阶 | 责任单元定位 | KB-009 |
| 异常衰减规律·进阶 | 三道工序与传导关系 | KB-001-B |
| 责任单元定位·进阶 | 三道工序与传导关系 | KB-001-B |

`approve_with_fix` 不再等于发布：必须生成新版本、保留修订谱系并重新审核；只有精确 `approve` 才能发布，超预算则安全失败。

### 3.8 正式评测与离线复算

- Seed A：50/50，失败 0；
- Seed B：50/50，失败 0；
- 每轮 50 份 `case_result.json` 和 50 份 `trace_v3.jsonl`；
- 60/60 严格覆盖格通过；
- 10/10 核心知识点完整闭环通过；
- 支持事实单元、适配节点和覆盖格自动拆分；
- 支持 `AUTO_PRELIMINARY` 与 fail-closed 的 `FINAL_HUMAN_REVIEWED` 两种复算模式。

## 四、当前系统可以做到什么

1. 根据岗位画像、岗前测和必要探针生成个性化学习计划；
2. 对 10 个核心知识点按基础、应用、进阶三档生成学习资源；
3. 让多个 Agent 并行生成、审核、辩护、修订和汇聚，而不是单纯串行调用；
4. 用真实数据库完成只读 SQL 实操，并对错误提供分级提示；
5. 根据真实回答调整知识点、难度、任务复杂度和追问策略；
6. 对历史错误先纠正，再决定升档或进入下一知识点；
7. 在反复失败时真降阶、换内容或延后学习，不无限循环；
8. 输出学习画像、路径、资源匹配、难度轨迹和训练报告；
9. 在协同视图查看 Agent 状态、并行审核、运行拓扑和会话日志；
10. 完整运行正式 50×2，并从 TRACE 离线复算竞赛指标。

