进阶层不只是"识别信号"，而是**对一个异常信号定可信度**：面对一个偏低的完成率，能判断它有多大把握是真异常，先排除各类假象，再给出分级结论，而不是见低就报。

## 1. 异常判定的处置状态分类

同样是"低于正常区间"，处置方式并不相同。按证据与性质分为三种处置状态：

- **可上报异常**：口径、计划和报工状态已核实，且出现显著单期偏离或连续异常——可作为异常上报。
- **待核实信号**：存在偏离，但证据不足或关键口径尚未核实——标记观察，补核后再定。
- **非生产性差异**：偏离可由数据、统计口径、报工状态或计划错配解释，不作为生产异常上报。

经核实的一次性扰动（设备故障、停电、极端天气、检验卡点等）属于**偶发业务异常**，是真实业务事件，**不属于非生产性差异**；是否上报取决于影响程度。持续性用于判断是否形成趋势，**不是异常成立的必要条件**。

（说明：这三档是本项目的处置框架，非行业统一标准；"可上报／待核实"是证据状态，"非生产性差异"是差异性质，用途不同，不要混判。）

## 2. 系统排除非生产性差异的顺序

拿到一个偏低信号，按以下顺序核验，再谈定性：

1. **口径核验**：聚合、周期、单位或对象范围是否错位？口径错会制造假偏低（详见月度聚合方法）。
2. **计划核验**：计划版本、计划对象是否匹配？计划错配造成的偏差不是生产异常（详见计划量与实际量口径）。
3. **报工状态核验**：是否存在报工滞后、补报、冲销、重复、漏报，或完工认定／质检确认／工作包关闭时点不一致？
4. **佐证核验**：延误、齐套、质量、报工状态、关键节点或现场记录等**独立佐证**是否与信号同向？（risk_level 与完成率异常同源，仅作分档与优先级提示，不计为独立佐证。）

前三步任一命中，信号降为"非生产性差异"；全部通过且偏差显著或持续，升为"可上报异常"；证据不足则为"待核实信号"。

## 3. 判定结论的边界

异常识别最多输出：**异常对象、期间、幅度、可信状态及待核验事项**。

它不能直接回答：偏低的**原因**是什么、是否存在**传导**、责任归属——根因、传导和责任分别进入后续知识点。进阶结论应写成"在某聚合口径下（口径、计划、报工均已核实），该对象完成率偏离正常区间，处置状态为某（可上报／待核实／非生产性差异），待核验事项为某"，把核验前提与处置状态一并写清。

## 4. 常见误区

1. 见完成率低就报异常，不做处置状态分类、不排除非生产性差异。
2. 跳过口径／计划／报工核验，直接把偏低当生产异常，把非生产性差异误报。
3. 把经核实的一次性扰动当成非生产性差异排除——它是真实偶发业务异常。
4. 把"持续多月"当成异常成立的必要条件，漏掉单期重大偏差需立即上报。
5. 拿 risk_level 当独立佐证——它与完成率异常同源，不增加证据独立性。
6. 把"识别到异常"等同于"找到了原因／传导／责任"，越出异常识别的边界。
