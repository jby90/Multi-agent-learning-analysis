跨工序归因**不是另造一个新指标**，而是对异常、对象依赖、时序、齐套和执行单元证据进行编排与综合判断，最终得到"候选源头 + 传导证据 + 证据缺口"，而不是一步锁定根因、更不是直接定责任。

## 1. 归因是编排各环节证据

归因把已有环节的产出组织起来，各司其职：异常识别（是否真异常、排除非生产性差异）、传导时滞（时序是否相容，不预设固定时滞）、异常强度沿链变化（收窄/保持/扩大候选，不预设衰减）、责任单元定位（成因候选与落点）、三道工序与传导关系（综合落传导证据）。**归因的价值是编排与综合，不是重新发明这些分析。**

## 2. 归因流程（按现场追查顺序）

1. **确认现象**：先通过异常识别确认目标异常及统计口径；
2. **锁定对象链**：确认船号、区域、工作包、托盘或物量对象及其前后置依赖关系（上溯对象是工作包/物量依赖链，不只是工序月度均值）；
3. **对齐时序**：在合理窗口内检查上下游异常是否时序相容；
4. **核验暴露**：确认下游是否实际受到交付、齐套或前序条件影响；
5. **排查替代解释**：共同因素、报工错位及下游本地问题；
6. **补充强度形态**：收窄、保持或扩大，仅作辅助证据；
7. **输出结论**：候选源头、疑似传导路径及证据缺口。

## 3. 结论是"疑似"，不是"锁定"

产出是"数据可见范围内候选源头为某，传导证据为某（由传导关系知识点落定），尚缺某证据"，而不是"根因就是某工序、由某单元负责"。数据序列只能支持到疑似，确认因果与责任需物料流转、齐套、交接等现场证据。

## 4. 常见误区

1. 把归因当成某一步的独立分析，跳过证据链直接下根因。
2. 只按工序月度均值上溯，不锁定工作包/物量依赖链。
3. 预设固定时滞、预设衰减，把"符合规律"当归因依据。
4. 沿链找到最早异常点就当确定源头，不留"候选、待核"余地。
5. 把候选源头直接判成责任单元，越过传导证据与现场证据。
