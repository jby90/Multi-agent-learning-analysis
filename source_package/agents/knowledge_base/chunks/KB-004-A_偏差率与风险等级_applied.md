基础层能解读偏差率的正负和风险等级的分级；应用层要用它们**做筛查、排序和分布对比**：从一批记录里快速锁定问题对象，并看风险在不同维度上怎么分布。

## 1. 筛查与排序口径

偏差率与风险等级是异常筛查的两个抓手：

- 先按项目风险等级筛出重点记录；
- 再在同一等级内按偏差率排序，识别完成偏差最重的对象。

风险等级用于"快速圈定"，偏差率用于"精确排序"。这是查询与看板的筛选路径；**实际处置优先级还应结合关键节点、齐套状态和恢复条件，不是仅凭这两个查询字段就完成综合风险排序**。区间聚合的偏差率仍用汇总口径：先汇总实际量与计划量，再算相对偏离，不对明细偏差率做算术平均。

## 2. 按维度对比风险分布

把风险等级或偏差率按维度分组，可以看风险集中在哪里：

- 按船号：哪条船的高风险记录最多，或整体偏差最重；
- 按工序：哪道工序风险最集中；
- 按月份：风险是否随时间加重或缓解。

对比时要注意可比前提：不同工序的数量口径可能不同，跨工序比较优先看各自的风险等级与偏差率，不直接比较绝对偏差量。

## 3. 风险等级与偏差率的关系

在本项目数据中，风险等级按偏差率阈值分档生成，两者不是两个独立的风险信号。延误天数（delay_days）是补充观察指标：它反映相对计划日期的滞后程度，用于复核管理紧迫性，但不参与风险标签的生成。因此：

- 是否影响关键节点或交船，不能只看延误天数——有剩余浮时的任务可能延误但不影响节点，无浮时的关键任务延误很少也可能影响节点；需结合关键路径、剩余浮时和下游衔接判断；
- 应用层筛查以系统风险等级做初筛、偏差率做量化排序、延误天数做紧迫性复核；
- 风险等级用于确定核查优先级，不直接回答"为什么偏差"。

## 4. 常见误区

1. 把"风险等级初筛＋偏差率排序"当成已完成的综合处置优先级，忽略关键节点、齐套与恢复条件。
2. 对明细偏差率做算术平均得区间偏差，正确做法是先汇总再相除。
3. 把风险等级当成原因判定，由"高风险"直接推出某种根因。
4. 把延误天数直接当成"已影响交付节点"，忽略剩余浮时与关键路径。
5. 跨工序直接比较绝对偏差量，忽略工序数量口径不可比。
