进阶层分析的目标不是只算出一个异常完成率，而是把异常落到“缺口集中在哪里、由哪类差额构成、当前数据能支持什么结论”。数据字段有限时，应把数据表现分解与业务根因判断分开：数据可以定位缺口、描述结构，但不能仅凭完成率、实际量和合格量直接完成现实中的定责。

## 1. 四步分析链

### 第一步：判级——确认是否进入下钻

先按加权口径算工序完成率和偏差率，按项目风险线判级。达到高风险的工序进入下钻分析。风险判级只触发分析、确定优先级，不直接证明已影响下游、一定存在产能不足、或某单元已构成责任主体。若数据带有源头异常标签，可作为分析起点，但不能替代现实因果验证。

### 第二步：定位——同时看“偏差程度”和“缺口贡献”

在异常工序内部按执行单元分组，先汇总计划量、实际量和合格量再算指标。定位时不能只按完成率升序认定“完成率最低的单元就是缺口集中地”：完成率表示单元自身偏差程度，正向欠量才表示该单元对整体欠量贡献了多少。

因此应区分两个结论：

- 偏差最严重单元：完成率最低；
- 缺口贡献最大单元：正向欠量最高。

两者可能是同一单元，也可能不同。汇总各单元缺口时，应把各单元的正向欠量相加（即毛缺口口径），不让超产单元抵消欠产单元；用于安排核查资源时，优先关注缺口贡献大且完成率低的单元。

> 说明：毛缺口口径按执行单元粒度计算，只避免执行单元之间的超产抵消，不能排除单元内部更细粒度（工作包、托盘）的抵消。若数据提供更低且不可替代的粒度，应先在最低粒度计算正向欠量，再逐级汇总。

### 第三步：分解——区分“产出不足”与“合格转化不足”

若数据同时提供计划量、实际量和合格量，可把“未达到合格计划的数量”分成两部分：

- 产出缺口：实际量未达到计划的部分（超计划时为零）；
- 合格转化缺口：计划范围内的实际产出中尚未转化为合格量的部分。

设计划量为 `P`、实际量为 `A`、合格量为 `Q`，数量均不小于零。为避免超产形成负缺口，按以下公式计算：

- 产出缺口：`D_output = max(P - A, 0)`；
- 合格转化缺口：`D_conversion = max(min(A, P) - min(Q, P), 0)`；
- 合格产出总缺口：`D_total = D_output + D_conversion`。

在数据满足 `0 ≤ Q ≤ A` 的正常数量约束时，`D_total = max(P - Q, 0)`。若出现 `Q > A` 等违反数量关系的记录，应先标记为数据质量问题，不继续用该记录作缺口归因。这组分解回答：合格产出不足主要是“实际产出没达到计划”，还是“计划范围内的产出尚未转化为合格量”。

业务名称必须准确：

- “计划减实际”应称为产出不足/进度缺口，不能直接称为产能缺口。产出不足还可能与设计未释放、物资不齐套、前序未交付、场地等待、计划调整或报工滞后有关。在托盘管理法下，应优先核查上游物量配套与齐套状态——上游未齐套可能形成本工序“无料可做”的表象，不能仅凭产出缺口认定本工序产能不足。
- “实际减合格”应称为合格转化缺口，不能直接命名为返工量。该差额可能包含待检、检验跨期、不合格、返工、报废或口径错位。

系统应优先输出两类缺口的贡献占比，而不是强制二选一。若比赛题要求给出主导类型，按确定规则：产出缺口贡献更大判“产能缺口（代理）”，合格转化缺口贡献更大判“质量返工（代理）”，两者相当或无缺口判“暂不可判定”。是否需要“混合型”须由项目配置显式定义阈值，不得由模型自行解释“显著”。该映射只兼容验收标签，不代表现场已确认产能不足或实际返工；对外业务表述仍优先用“产出不足”和“合格转化不足”。

### 第四步：核验——把数据结论与业务根因分层输出

基于当前字段可直接支持：哪道工序达到高/中风险、哪个执行单元贡献最大正向欠量、缺口主要是产出不足还是合格转化不足、是否存在源头异常标签及应优先检查的下游对象。

当前字段通常不能单独支持：产能不足（需工时、设备负荷、停机等待数据）、质量返工（需返工工单、检验状态）、责任定性（需设计、物资、前序交付条件）、已造成下游影响（需工序依赖、交付日期、缓冲量）。因此执行单元宜称“缺口集中单元/优先核查单元”，补充证据确认可控原因后才进入正式定责。

## 2. 下游预警的正确用法

在托盘管理法/中间产品导向的建造模式下，上游工序欠产可能通过物量配套链增加下游齐套风险：预处理供料不足，可能影响制作托盘的集配齐套，进而影响安装托盘。是否传导、何时传导取决于在制缓冲量与计划衔接，不应固定写成“本月上游异常必然导致次月下游异常”。若带源头异常标签，应结合项目工序链与时滞规则，检查下游工作包在相关计划时间窗口内是否存在风险，结论写成“需核查下游影响”，而非“已经造成下游异常”。

## 3. 数据示例的分析顺序

以某船某月高风险工序为例，按以下顺序分析：先按执行单元汇总计划量和实际量、算各单元完成率与产出缺口贡献；定位产出缺口贡献最大的单元，再看其完成率是否也处于低位；对该单元看实际量与合格量的差额，判断是否存在明显合格转化缺口；输出“缺口集中单元＋缺口结构＋风险程度＋待核验事项”，不直接把差额命名为产能不足或质量返工；若带源头异常标签，再按配套链检查下游时间窗口。

## 4. 推荐结论模板

> {船号}{月份}{工序}完成率为{完成率}、偏差率为{偏差率}，判为{风险等级}。产出缺口主要集中在{执行单元}，该单元贡献整体产出缺口的{贡献占比}，自身完成率为{单元完成率}。分解显示当前以{主要表现}为主。基于字段可确认缺口位置和结构，但尚不能直接认定“产能不足”或“质量返工”，分别需要{待核验数据}验证。{如有源头异常标签则补充下游核查提示。}

## 5. 可接受与不可接受的表述

可接受：某单元贡献了该工序大部分产出缺口，且合格转化缺口较小，因此当前异常主要表现为实际产出不足；产能、物资或计划原因仍需核验。

不可接受：某单元完成率最低，所以该单元产能不足并应承担责任。

可接受：实际量与合格量之间存在较大差额，说明合格转化不足，需检查检验状态、不合格记录和返工记录。

不可接受：实际量减合格量就是返工量，因此根因是质量返工。

## 6. 常见误区

1. 把高风险判级当成根因结论或下游影响事实。
2. 只按完成率排序，把“比例最低”误当成“缺口贡献最大”。
3. 把“实际减合格”直接命名为返工量。
4. 把“计划减实际”直接命名为产能不足（托盘管理法下应优先核查上游配套齐套，上游未齐套可能形成“无料可做”表象）。
5. 看到执行单元就直接定责，不核验设计、物资、前序和现场条件。
6. 把源头异常标签当成已证明的因果链，固定推断到次月下游工序。
7. 忽略超产情形，把超计划的负差额当欠产缺口，未对缺口取正。
