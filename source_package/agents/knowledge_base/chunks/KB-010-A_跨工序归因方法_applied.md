基础层知道"归因是编排、结论只到疑似"；应用层要**实际串起一次归因**：从一个下游异常出发，在同一对象依赖路径与合理时滞窗口内依次调用各环节产出，构造一条前后衔接、每步可复算的证据链，输出候选源头与传导候选。

## 1. 串一次归因的操作顺序

1. **确认现象**：目标下游确为异常（先过异常识别，排除非生产性差异）；
2. **锁定对象链**：确认船号、区域、工作包、托盘或物量对象及前后置依赖，后续上溯在此对象链内进行，不只按工序月度均值；
3. **沿对象链上溯找候选源头**：**在同一对象依赖路径和合理时滞窗口内，最早出现的相关异常，作为数据可见范围内的候选源头**（时序相容只到候选，不预设固定时滞）；
4. **下钻源头与落点两端单元**：分别下钻候选源头单元和下游异常落点单元，判断源头集中位置、下游承接位置及是否存在本地叠加（不只在源头工序定位）；
5. **交传导判断**：把时序相容性、强度形态、依赖路径、齐套线索交三道工序与传导关系知识点落传导证据。

## 2. 上溯的两条纪律

- **不能因工序汇总值正常就停止上溯**：应确认具体工作包、托盘或执行单元未被汇总抵消，且下游未暴露于其缺口，才暂止该路径；
- **多个上游工序异常时，不全部自动列为候选源头**：只有**同时满足"位于相关依赖路径 + 时序相容 + 对象能够对应"**的，才列入候选，交后续证据收窄。

## 3. 证据链要完整可复算

每一步都要有对应查询结果支撑，缺口显式标"待核"：每个候选源头、每段时序相容、每个强度形态都对应可复算查询；缺少的齐套/交接/现场证据标为待核，不推断填补；结论写成"数据可见范围内候选源头为某，传导证据为某（交传导关系知识点落定），尚缺某证据"。

## 4. 常见误区

1. 不先过异常识别就上溯，把非生产性差异当成异常源头。
2. 只按工序月度均值上溯，不锁定工作包/物量依赖路径。
3. 因工序汇总正常就停止上溯，忽略工作包被汇总抵消、下游已暴露于其缺口。
4. 多上游异常时全部列为候选，不按"依赖路径+时序相容+对象对应"筛。
5. 只在源头工序定位单元，不同时下钻下游落点单元判本地叠加。
