进阶层要面对跨工序归因真正的难点：**多个候选源头、混合情形、证据缺口并存时，如何给出带不确定性、但仍可复算的归因结论**，而不是硬选一个源头、硬下一个根因。归因的上限由数据支持决定，进阶层要说清"数据支持到哪、哪里必须留待现场核验"。

## 1. 多候选源头的收窄，不是硬选

上溯得到多个候选源头时，用证据逐步收窄：**时序**（哪个候选与下游更相容）、**依赖路径**（哪个与下游确有工作包/物量配套关系）、**齐套暴露**（下游是否确实暴露于该候选的缺口）、**排除共同因素**（多候选是否其实由同一外部因素造成，那样源头是共同因素而非某工序）。收窄后仍并列的，如实保留多候选，不强行定一。

## 2. 传导与本地叠加可同时成立

**排除本地叠加不是支持传导的必要条件**：时序相容、对象依赖成立且确认下游发生齐套或交付暴露，即可**支持该路径存在传导**；若同时存在下游本地异常，则标记为**混合情形，不否定传导本身**。有本地异常证据（设备/质量/物资/报工）才标"存在本地叠加"，否则标"扩大原因待核"。

## 3. 用两轴输出，不混维度

传导判断分两个独立的轴，不要混成一维：

- **传导证据（强度）**：支持 / 疑似 / 证据不足；
- **本地叠加（原因构成）**：有 / 无 / 待核。

（若验收必须用四态：支持传导/疑似传导/证据不足/混合异常，则将"混合异常"明确为组合标签——**混合异常＝传导证据成立或疑似，同时存在下游本地异常证据**。）

候选源头与传导路径也分两层表述：**传导路径**证据充分时写"支持该路径存在传导"；**候选源头**仍写"数据可见范围内候选源头"——因为最早异常节点不一定是最终业务根因。

## 4. 统一结论模板

"在同一对象依赖路径和候选时滞窗口内，{上游工序／执行单元}较早出现异常，{下游工序／执行单元}随后出现偏离，并已发现／尚未取得{齐套、交接或物量暴露证据}。当前传导证据为{支持／疑似／不足}，数据可见范围内候选源头为{对象}；下游本地叠加状态为{有／无／待核}。该结论用于定位异常路径和待核事项，不直接构成根因确认或责任认定。"

## 5. 归因方法的边界

跨工序归因能给出：可复算证据链、候选源头（可多候选）、强度形态、传导证据强度与本地叠加两轴、证据缺口清单。

它不能给出：确认的因果（需现场证据，由传导判断结合现场落定）；责任归属（候选源头或落点单元都不等于责任）；精确时滞或衰减量（示例非普适、衰减非规律）。归因只把证据组织到"疑似"这一步，因果与责任交给传导判断和现场。

## 6. 常见误区

1. 多候选时挑数字最差的硬定一个，不用时序/依赖/齐套收窄。
2. 把"存在本地叠加"当成否定传导的理由——两者可并存。
3. 把传导证据强度和本地叠加混成一维，或把候选源头当已证根因。
4. 证据链有缺口仍硬给确定源头，不落"证据不足"。
5. 把候选源头或落点单元直接判成责任，越过传导证据与现场证据。
