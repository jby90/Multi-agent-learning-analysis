# 创新 A+B 未到终点归因与消融实验审计

- 审计日期：2026-07-29
- 改进前正式评测提交：`5d0dd26`
- 创新 A+B 冻结提交：`6e2042e`
- 最终文档提交：`9ad5623`
- 审计问题：正式 50×2 中 4 次未到达 `S10_DONE`，是否由创新 A 或创新 B 造成；现有消融实验是否真实完成、能够证明什么。

## 一、结论先行

### 1. 未到终点不是创新 A/B 的直接结果

现有证据支持以下结论：

> 正式 50×2 中的 4 次未到终点，不是创新 A 或创新 B 的执行路径直接造成的；它们分别由既有 R-04 讲义预检和既有 SQL 权限门对本轮随机生成偏差执行 fail-closed 所致。

理由不是只看相关性，而是同时满足四类证据：

1. **控制流不可达**：4 个样例都在创新逻辑可能介入之前停止。
2. **核心组件未改变**：正式 runner、ReviewAgent、SQL 沙箱、状态转移和状态机引擎在改进前后 Git blob 完全一致。
3. **同一冻结代码跨轮互换**：同一样例在创新版一轮失败、另一轮成功，符合模型输出波动，不符合创新逻辑确定性致错。
4. **改进前后到达率完全相同**：两轮分别仍为 49/50 和 47/50；失败类型数量也相同，只是落到不同样例。

因此不建议为了这 4 个停止回滚 A/B。回滚不会消除讲义预检生成偏差或 SQL 输出越权问题，反而会丢失已经通过消融验证的受控辩护和边际选靶能力。

### 2. 但不能夸大为“统计学上已经证明 A/B 对所有到达率绝对无影响”

当前没有做“将完全相同的真实 LLM 原始输出分别喂给改进前、改进后正式 runner”的全矩阵配对重放，也没有做大样本随机化显著性检验。因此可作出的严格表述是：

- 已排除这 4 个观测停止与 A/B 的直接控制流因果关系；
- 改进前后两轮到达率和失败类型计数没有回退；
- 尚不能用本次 50×2 声称 A/B 对任意未来模型输出的到达率都绝对没有间接影响。

## 二、“未到终点”具体指什么

创新版两轮共执行 100 个 attempt，每例只执行一次，没有重试、续跑或换参数：

| 结果 | 数量 | 含义 |
|---|---:|---|
| `completed` | 96 | 到达 `S10_DONE` |
| `safe_rejected` | 2 | 安全门主动拒绝，错误 SQL 未执行；不是静默失败 |
| `system_error` | 2 | 讲义连续三次未通过 R-04 预检，流程 fail-closed |

“4 个未到终点”不是同一种问题：

- 2 个 `safe_rejected` 是安全系统按设计工作，但学习流程没有完成；
- 2 个 `system_error` 是生成可靠性问题，需要后续增强兜底。

## 三、4 个样例逐例归因

### 1. Round 1 / E2E-018

- 结果：`system_error`
- 最后状态路径：`T01 → T02`
- 错误：`lecture failed review preflight after 3: R-04`
- Trace 只有 6 条消息，停在画像、诊断和学习契约之后。
- `_lecture_draft()` 连续生成三次讲义，每次都未通过既有 `preflight_r04()`，因此没有产出可进入正式 Review 的讲义。
- 没有 `rebuttal_case`，没有执行选择性辩护、确定性让步、关系选靶或覆盖提交。

直接原因：模型生成的讲义出现证据未直接支持的连接性/结构性表述，R-04 预检拒绝放行。

与 A/B 的关系：**无直接关系**。创新 A 的辩护只处理正式 Review 后的 R-02/R-03；该样例尚未进入正式 Review。创新 B 只作用于自由追问选靶；该样例尚未进入自由追问。

### 2. Round 2 / E2E-012

- 结果：`system_error`
- 最后状态路径：`T01 → T02`
- 错误和停止位置与 E2E-018 相同：讲义三次命中 R-04 预检。
- 没有辩护消息，也没有误区关系路由和覆盖状态。

直接原因：本轮讲义随机生成连续三次未满足既有 R-04 证据结构约束。

与 A/B 的关系：**无直接关系**，理由与 E2E-018 相同。

### 3. Round 2 / E2E-003

- 结果：`safe_rejected`
- 状态路径：`T01 → T02 → T03 → T04 → T09 → T10 → T11 → T21`
- 模型生成 SQL 使用了 `p.process_order` 作为输出和分组维度。
- 任务模板 `T-03` 的查询权威只允许输出 `process_code` 与 `complete_rate`。
- SQL 沙箱以 `S-04: output columns do not match the Q6 contract` 拒绝。
- SQL 没有进入数据库执行。

直接原因：SQL 生成模型偏离任务模板的输出列权限。

与 A/B 的关系：**无直接关系**。runner 在收到 `T21` 后立即抛出 `safe_rejected`，发生在 Review 和 `RebuttalGenerator.generate()` 之前；创新 B 不参与 SQL 生成或沙箱判定。

### 4. Round 2 / E2E-005

- 结果：`safe_rejected`
- 状态路径与 E2E-003 相同。
- 生成 SQL 同样使用 `p.process_order`，而权威要求 `process_code`。
- 同样由既有 `S-04` 权限门拒绝，SQL 未执行。

直接原因和 A/B 关系与 E2E-003 相同。

## 四、同一创新代码跨轮对照

如果某项确定性创新逻辑必然导致某个样例停止，那么同一冻结代码、同一用例通常应稳定复现。实际结果相反：

| 样例 | 创新版 Round 1 | 创新版 Round 2 |
|---|---|---|
| E2E-003 | 完成 | SQL 安全拒绝 |
| E2E-005 | 完成 | SQL 安全拒绝 |
| E2E-012 | 完成 | 讲义 R-04 预检失败 |
| E2E-018 | 讲义 R-04 预检失败 | 完成 |

四个样例在相同代码 `6e2042e` 下都出现过成功结果，停止位置取决于当轮生成内容。这是模型输出波动被既有安全门捕获的直接证据。

缓存请求哈希进一步排除了“输入提示发生变化”的解释：

| 样例与调用 | 成功轮请求 SHA-256 | 失败轮请求 SHA-256 | 观测 |
|---|---|---|---|
| E2E-018 首次讲义生成 | `d945c857628ddf94b2dd48cfdaf381c63cd9d7187ddf7d8fe48f66425b5ab0cf` | 相同 | Round 2 成功，Round 1 连续预检失败 |
| E2E-012 首次讲义生成 | `d54e14981851b2fc97e75282d2b6cf7e24fe1725c4ca228e7651c12bf233c6f9` | 相同 | Round 1 成功，Round 2 连续预检失败 |
| E2E-003 SQL 生成 | `5a2871f6c01cb4971a8e37266fb8984d0226eb81950560b13b08cc9fa4267f20` | 相同 | Round 1 生成 `process_code`，Round 2 生成越权 `process_order` |
| E2E-005 SQL 生成 | `5a2871f6c01cb4971a8e37266fb8984d0226eb81950560b13b08cc9fa4267f20` | 相同 | Round 1 生成 `process_code`，Round 2 生成越权 `process_order` |

这里的 request SHA-256 来自持久化 LLM 缓存请求对象，覆盖模型和实际请求内容。即使请求相同，远端生成模型仍可能返回不同答案；安全门据返回内容决定放行或拒绝。

1. A 的固定桩组件消融：已做；

## 八、改进后的总体效果

### 已验证的正向变化

1. **创新 A 降低无效模型辩护上界**：固定事务中模型辩护尝试由 2 次降至 1 次，第二次改为确定性让步，同时保持完整复审。
2. **创新 A 收紧反馈边界**：生成器只接收白名单教学修改要求，不接收原始 Review 工程理由。
3. **创新 B 抑制已覆盖关系上的无收益跳转**：固定可达历史中零收益跳转和重复贡献均由 1 降为 0。
4. **覆盖提交更可靠**：只有最终 Review 通过且后端复算一致时才原子提交；拒绝、异常、幂等重放不污染覆盖状态。
5. **第二域安全退化**：无关系可用时 B0/B1 公开行为等价，覆盖为空且没有主域串入。

### 正式指标与边界

| 指标 | 创新版 Round 1 | 创新版 Round 2 |
|---|---:|---:|
| 幻觉率 | 2/987 = 0.2026% | 2/973 = 0.2055% |
| 知识覆盖率 | 10/10 = 100% | 10/10 = 100% |
| 自动适配率 | 163/163 = 100% | 159/159 = 100% |
| 到达终点 | 49/50 = 98% | 47/50 = 94% |

三项正式指标均达到最高档阈值，到达率未比改进前下降。需要继续如实披露：改进前两轮幻觉事件分子为 0，创新版两轮为 2；这些 R-02 草稿事件被 Review 捕获且没有直接放行，但不能表述为“绝对零幻觉不回退”。该变化与本报告讨论的 4 个未到终点不是同一问题。

## 九、下一步建议

### 1. 不回滚 A/B，单独提升生成到达率

对 R-04 预检失败建议：

- 保留 R-04，不放宽硬门；
- 将前一次具体不支持的句子转成受控、去工程术语的重生成约束；
- 达到次数上限时使用引用约束的抽取式讲义兜底，而不是直接生成自由连接性表述；
- 新增固定桩验证兜底讲义仍通过 R-01～R-06。

对 SQL 安全拒绝建议：

- 保留 S-04 和 T21，不允许越权 SQL 直接执行；
- 在第一次权限门失败后，使用任务 `query_authority` 对输出列做一次确定性重写或受控再生成；
- 只允许白名单列和已有模板关系，第二次仍失败才安全拒绝；
- 单独统计“首次拒绝后安全修复率”，不并入幻觉率。

### 2. 补一项更强的配对因果实验

为了把“高可信非直接因果”升级为更强证据，可新增正式 runner 配对重放：

1. 冻结同一批原始 LLM 响应缓存；
2. 分别在 A0/B0 与 A1/B1 代码上重放；
3. 对每个 case 比较第一次状态分叉、停止位置、到达状态和成本；
4. 禁止重新调用模型、补样本或只重跑失败样例；
5. 分别报告控制流等价、A/B 实际触发样例数和到达率差异。

该实验是后续增强项，不影响当前结论：本轮 4 个停止发生在 A/B 触发前，不能归因于创新改造。
