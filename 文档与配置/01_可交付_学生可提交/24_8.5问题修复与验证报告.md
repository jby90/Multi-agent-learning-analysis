# 8.5 问题修复与验证报告

## 一、修复范围

本轮只处理 8.5 测试报告中确认需要优先修复的四组问题，不改变状态机的 21 条转移、三指标算法、多智能体审核门和确定性裁决原则。

1. 问题 6、7：当前难度显示与轨迹重复升档。
2. 问题 1：微课正文中的业务字段被 `snake_case` 规则误拦截。
3. 问题 5：知识点或任务切换后仍残留上一题 SQL 草稿。
4. 问题 2：安全结束时只有笼统提示，无法区分失败原因和审核次数。

## 二、逐项修复结果

### 1. 当前难度唯一数据源与轨迹去重

修复内容：

- 后端交互状态新增 `current_difficulty`，按“当前活动任务 → 当前学习任务 → 学习契约 → 岗前诊断”顺序确定唯一值。
- 学员画像的“当前档位”和难度轨迹共同使用该值。
- 当培养路径已经给出目标 `difficulty` 时，前端直接采用该值，不再对同一个 `step_up` 重复计算。

预期效果：

- 升档后“当前档位”同步变化。
- 难度轨迹不再出现“应用档突然跳进阶档、随后又回应用档”的假跳变。

专项验证：

- 前端难度与画像测试：14 项通过。
- 后端升档状态测试：1 项通过。

### 2. 微课业务字段与内部协议字段分流

修复内容：

- 删除“任意下划线英文词都整段隐藏”的过宽规则。
- 仅明确拦截 `trace_id`、`transition_id`、`msg_id`、`rule_hits` 等内部协议字段。
- 为生产进度表、风险等级、延迟天数、缺口强度、工序、船号、月份等业务字段补充中文映射。
- 查询结果表仍然采用字段白名单；未知列名继续显示为“数据字段”，避免内部字段泄漏。

预期效果：

- 合法微课不再因为包含业务表名或字段名而整体显示“当前内容暂时无法展示”。
- 工程协议字段仍保持 fail-closed，不向学员泄漏。

专项验证：

- 微课呈现、资源面板、画像测试：125 项通过。
- 全量回归额外发现并修复未知查询列名误放行问题。

### 3. 任务切换时清除 SQL 草稿

修复内容：

- 前端根据会话、知识点、任务模板、难度和题目生成“当前任务身份”。
- 轮询发现任务身份发生变化时，清空上一题 SQL 草稿并重置教师提示层级。
- 同一任务的超时、网络重试或查询错误不会清空草稿，学员仍可继续修改。

预期效果：

- 进入新知识点、新模板或升降档任务后，编辑框为空。
- 留在原题纠错时，错误 SQL 保留。

专项验证：

- 实操组件测试：56 项通过。

### 4. 安全结束原因码与审核次数

修复内容：

- 后端增加三个稳定原因码：
  - `model_unavailable`：内容生成服务不可用；
  - `evidence_insufficient`：当前内容缺少足够证据支持；
  - `review_exhausted`：在限定审核次数内仍未通过质量门。
- 后端同时返回 `review_attempts` 和 `review_limit`。
- 学员端用中文显示结束原因、实际审核轮数和上限，并明确说明未通过审核的内容没有交付。

预期效果：

- 教师和学员能够区分服务故障、证据不足与多轮审核失败。
- 不再把所有安全结束误解为同一种模型错误。

专项验证：

- 后端原因分类与轮次测试：通过。
- 前端安全结束说明测试：通过。

## 四、学生手动验证步骤

### A. 验证当前难度与轨迹

1. 选择任意岗位并完成岗前测评。
2. 记录右侧岗位画像的“当前档位”。
3. 完成基础任务和理解核对，触发“已提高一档难度”。
4. 检查“当前档位”、练习题难度标签和完整学习画像中的难度轨迹。
5. 三处应显示同一档位；轨迹只能升一级，不能先跳两级再回落。

### B. 验证微课字段显示

1. 选择“新入职生产计划员”，岗前测评可故意多答错几题。
2. 打开岗位微课，逐页查看关键数据、正文和证据。
3. 页面不应出现“当前内容暂时无法展示，请稍后再试”。
4. `actual_qty`、`risk_level` 等业务字段应显示为“实际完成量”“风险等级”等中文名称。
5. 若导入含 `trace_id` 或 `transition_id` 的异常材料，学员端应隐藏该内容。

### C. 验证 SQL 草稿清理

1. 在当前实操题中输入一段 SQL，但不要提交。
2. 通过完成任务或补学流程进入另一个知识点、另一模板或新的难度档。
3. 新任务的 SQL 编辑框应为空。
4. 再输入一条错误 SQL 并提交；若系统仍停留在同一题，原 SQL 应保留，便于修改。

### D. 验证安全结束说明

该功能通常需要固定测试桩或教师测试环境触发，不建议学生故意破坏正常会话。

1. 使用测试桩分别模拟模型不可用、证据不足和多轮审核失败。
2. 安全结束页面应分别显示对应中文原因。
3. 页面应显示“已完成 X/Y 轮质量审核”。
4. 页面不得展示 `R-02`、状态机编号、内部异常栈或模型密钥。
5. 协同视图和调试工作台可保留工程日志，但学员主界面只能展示教学语言。

## 五、架构守护结论

本轮修改只增强状态可观测性、前端一致性和失败可解释性：多智能体生成、并行审核、选择性辩护、确定性裁决、T17 补学与 deferred 退出机制均未被删除或绕过。
