# 设计05：编排器状态机

> `orchestrator/transitions.py` 是状态拓扑的唯一真源；系统共有 21 条显式转移 T01–T21。运行时当前领域的 T18 guard 由 `orchestrator/engine.py:339-354` 判定，并由 `orchestrator/demo_session.py:240-245` 注入当前领域错因集合。

## 状态职责

| 状态 | 含义 |
|---|---|
| S0_INIT | 建立会话并载入画像 |
| S1_DIAGNOSIS | 前测诊断 |
| S2_KNOWLEDGE | 生成个性化讲义 |
| S3_TASK | 生成首题、结论题或进阶任务 |
| S4_VERIFY | 安全执行查询并形成证据 |
| S5_REVIEW | 审核产物 |
| S6_DEBATE | 被驳回方依据证据辩护，随后复审 |
| S7_STUDENT | 等待学员操作或自由文本作答 |
| S8_PROBE | 进行理解核对与反证学习 |
| S9_PATH_UPDATE | 更新难度与学习路径 |
| S10_DONE / S_FAIL | 完成 / 安全终止 |

## 自由文本理解核对

- S7/S8 接受学员自由文本，由学员完整表达判断依据。
- 理解核对共 2–4 轮：至少完成第二轮才可结束，第四轮必须安全收敛。
- 每一轮问题只能使用当前领域错因词汇、当前任务标准题面和证据；无来源数字、答案泄漏和工程词会被拒绝。
- 动态问题复用审核—辩护—复审闭环，只有获批问题才能展示；未获批草稿留在内部审计链。
- 纠正后进入真实进阶或完成；仍需巩固时进入降维讲义；无法识别时经 T18 返回教学提示。

## 核心不变量

1. 讲义、任务、数据结论以及动态问题均不得绕过审核。
2. 审核与追问都设置有限循环，不存在无限重试。
3. 查询未形成可靠结论时不进入 S5，不执行错误 SQL，不生成数据结论。
4. 答对后的进阶任务必须真实生成并再次审核；越过最高档时直接完成，不伪造任务。
5. 每次状态变化写入 trace，可从消息与依据完整复算。
