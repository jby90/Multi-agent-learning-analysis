# V4 正式 50×2 评测与人工终审操作手册

## 1. 本轮评测证明什么

- Seed A、Seed B 各自完整运行同一组 50 例，目录、TRACE、缓存互相隔离。
- 所有案例均从岗位画像、5 题前测和必要的固定校准探针进入生产路由。
- 正式运行不得注入 `knowledge_point`、`template_id` 或任何 `expected_*` 金标字段。
- 30 个指定案例构成 `10 个核心知识点 × 基础/应用/进阶 3 档`覆盖矩阵。
- 其余 20 例用于反证纠偏、同档换内容、二错降阶等压力测试，不重复计入覆盖率。

自动初算只能标记为 `AUTO_PRELIMINARY`。最终成绩必须完成双人复核；两人意见不一致时必须填写仲裁列。

## 2. 为什么 V4 需要专用复算器

V4 的一个正式案例可能先学习必要的前置知识，再到达评测目标知识点，因此 `case_result.json` 中可能包含多个真实会话。

专用复算器 `eval/v4_recompute.py` 使用以下口径：

- 幻觉率与幻觉拦截率：读取整条真实路由旅程中所有会话的最终发布事实单元；
- 正式适配节点与覆盖格：读取唯一的目标知识点会话；
- 不把首个前置知识点误当成评测目标；
- 不读取生产输入中的金标，金标只在 TRACE 写完后离线合并。

禁止使用旧的 `eval/v3_recompute.py` 直接计算 V4 结果，否则会把“先修后到达”误判为路由失败。

## 3. 运行顺序

在 `source_package` 目录执行：

```powershell
# 1. 路由门禁
.\.venv\Scripts\python.exe -m eval.v4_route_gate `
  --output eval/results/v4_route_gate.json

# 2. Seed A，必须完整 50 例
.\.venv\Scripts\python.exe -m eval.v4_formal_runner `
  --seed seed_A `
  --mode live `
  --output-dir eval/results/v4_formal_final/seed_A

# 3. Seed B，在 Seed A 完成后独立运行
.\.venv\Scripts\python.exe -m eval.v4_formal_runner `
  --seed seed_B `
  --mode live `
  --output-dir eval/results/v4_formal_final/seed_B

# 4. 自动拆表与初算
.\.venv\Scripts\python.exe -m eval.v4_recompute `
  --run-dir eval/results/v4_formal_final/seed_A `
  --run-dir eval/results/v4_formal_final/seed_B `
  --output-dir eval/results/v4_formal_final/recompute `
  --mode AUTO_PRELIMINARY
```

任何代码、Prompt、模型、温度、领域知识库或配置改变后，Seed A 和 Seed B 都必须重新完整运行，不能只补跑失败案例后拼接进旧轮。

## 4. 自动初算输出

`recompute` 目录至少包含：

- `facts_v4.json`：全旅程事实内容单元；
- `adaptation_nodes_v4.json`：目标场景应有适配节点与实际动作；
- `coverage_30_cells_v4.json`：每个 Seed 独立保留 30 个覆盖格，因此完整 50×2 共 60 行；
- `metrics_auto_preliminary_v4.json`；
- `metrics_auto_preliminary_v4.md`；
- `human_review_template_v4.json`；
- `03_TRACE字段与指标计算模板_v4_自动初算.xlsx`。

Excel 固定为 5 张表：

1. `00_指标汇总`
2. `01_TRACE字段`
3. `02_事实内容单元`
4. `03_适配节点`
5. `04_覆盖30格`

自动列不得覆盖。学生只填写各表末尾的 `reviewer_a*`、`reviewer_b*` 和必要的 `adjudicator*` 列。

## 5. 覆盖矩阵的指定案例

每个知识点的 5 个场景中，只有以下 3 个进入三档覆盖矩阵：

| 学员脚本 | 覆盖档位 | 证明内容 |
|---|---|---|
| `S-STEP-UP-B` | 基础 | 基础档讲义—实操—测验—反馈闭环 |
| `S-STEP-UP-A` | 应用 | 应用档讲义—实操—测验—反馈闭环 |
| `S-REBUTTAL` | 进阶 | 纠偏后升档产生的进阶资源及再审核闭环 |

`S-REFRESH` 与 `S-DOWNSTEP` 是鲁棒性压力案例，不得再把基础重学案例伪装成进阶覆盖。

## 6. 双人复核与最终复算

填写初算工作簿的人工列后执行：

```powershell
.\.venv\Scripts\python.exe -m eval.v4_recompute `
  --run-dir eval/results/v4_formal_final/seed_A `
  --run-dir eval/results/v4_formal_final/seed_B `
  --output-dir eval/results/v4_formal_final/final `
  --mode FINAL_HUMAN_REVIEWED `
  --human-review-workbook eval/results/v4_formal_final/recompute/03_TRACE字段与指标计算模板_v4_自动初算.xlsx
```

以下任一情况都会报错并拒绝生成最终成绩：

- 任一事实单元缺少双人标签；
- 两名复核者结论不一致但未仲裁；
- 幻觉标签未绑定 R-01/R-02/R-04/R-05/R-06 中至少一条规则；
- 任一 R-03 首次生成事务缺少双人标签；
- 任一覆盖格缺少双人门禁结论；
- Seed A 或 Seed B 不是完整 50 例；
- 正式运行不是 `production` 路由。

## 7. 指标解读边界

- 画像—资源难度适配准确率：正式赛题核心指标，检查目标会话初始画像、知识点、难度与资源是否匹配；
- 动态有效调整率：诊断性指标，只统计真实改变路径、难度、任务复杂度或追问的节点；正确的 `keep` 可审计但不计入“发生变化”的分子；
- 两者不可混用，也不能通过删除稳定保持节点来美化动态有效调整率。
