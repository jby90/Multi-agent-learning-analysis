# 7-31 问题核查更新记录与下一阶段修改计划

> 文档日期：2026-08-03
>
> 当前基线：最新本地交付代码
>
> 文档用途：说明 7-31 测试问题的处理进度，并约束下一阶段升级不破坏多智能体架构、赛题要求和现有评测口径。

## 一、总体结论

7-31 测试中暴露的问题没有全部消失，但影响会话安全和教学闭环的核心故障已经得到控制：

- 题目复述不再允许判定为掌握；
- 历史错误未纠正时，当前一题答对不再直接完成知识点；
- T17 已能真正降档、限制补学次数并以 `deferred` 优雅退出，不再无限循环；
- SQL 连续失败已经具有分级提示和第五次降阶机制；
- 追问题已经具备历史去重、误区和关系覆盖选靶能力。

目前仍需重点解决三个结构性问题：

1. 前测仅覆盖 5 个知识点，尚未形成完整的逐知识点诊断；
2. 下一知识点仍可能继承上一知识点的最终难度；
3. 系统生成的纠错说明尚未完全绑定学员真实错误，存在“推断出的误区被写成学员已经说过”的风险。

## 二、架构与评测守护边界

下一阶段修改必须保持以下边界不变：

- 不改变 21 条正式状态转移的编号、方向和审核语义；
- 不改变领域知识、实操任务、数据验证、专业审核等 Agent 的职责边界；
- 不删除创新 A“生成 → Review → 选择性辩护/受控反馈 → 再审核 → 安全收尾”；
- 不删除创新 B“误区关系候选 → 边际覆盖选靶 → Review 批准后计入覆盖”；
- 不放宽 R-01～R-05、S-01～S-09 和 SQL 只读白名单；
- 不修改幻觉率、适配率、知识覆盖率的既有计算算法；
- 不把 LLM 单次判断、置信度或措辞流畅程度直接当作“掌握”证据；
- 第二域继续复用相同的 Agent 接口、关系函数、状态语义和 Review 门禁；
- 前端只展示教学语言，不泄漏状态编号、内部规则编号、提示词和工程术语。

## 四、下一阶段推荐修改计划

### 阶段 0：冻结当前基线和新增失败测试

目标：先把现状固化，避免后续修改产生无法定位的回归。

实施内容：

1. 保存当前代码提交和当前非 live 测试结果；
2. 为 O-01～O-05、R-01～R-06 分别补充失败测试；
3. 开发期间统一使用固定桩，并排除 `live`；
4. 保存三个指标、创新 A/B、第二域回归的当前结果作为对照基线。

验收标准：新增测试在修改前能够稳定失败，且失败原因与目标问题一一对应。

### 阶段 1：逐知识点难度计划与历史纠错票据

目标：修复最明确的教学状态问题，同时不改变现有状态机。

#### 1.1 每个知识点独立定档

在诊断结果中增加逐知识点学习计划，例如：

```text
knowledge_point_id
initial_difficulty
difficulty_source = pretest | profile | default
diagnosis_status = mastered | weak | unassessed
```

进入下一知识点时从该知识点自己的 `initial_difficulty` 开始，不再继承上一知识点的最终难度。

#### 1.2 证据绑定的纠错票据

为每个真实错误保存结构化票据：

```text
source_round
learner_answer_digest
missing_evidence_fields
misconception_id
correction_evidence
resolved
```

纠错文案只能引用票据中的真实回答和证据；如果只有模型推断，没有学员原话，不得使用“你刚才把……当成……”这类确定性表达。

升档前必须满足：当前题通过，且阻塞完成的纠错票据均已结清。

验收标准：

- basic 知识点完成后，下一知识点仍可从其自身的 applied/basic 档开始；
- 学员回答“不会”时，系统不会虚构具体误区；
- 一道正确答案不能结清无关的历史错误；
- 状态转移编号和 Review 语义不发生变化。

### 阶段 2：前测覆盖和逐知识点诊断升级

目标：让前测真正决定“学什么、从什么难度开始”，而不是只生成一个总分。

推荐采用“分层自适应前测”，而不是简单固定增加到 10 道：

1. 第一层保留 5 道短题，覆盖五个核心能力簇；
2. 根据画像先验和第一层错项，追加最多 5 道定向题；
3. 最终必须为全部 10 个知识点生成 `mastered/weak/unassessed` 状态；
4. 未测试且无画像证据的知识点标记 `unassessed`，不得静默跳过；
5. 由逐知识点证据决定各自初始难度，不再只按总正确率统一定档。

推荐默认策略：

| 诊断情况 | 初始处理 |
|---|---|
| 有画像盲区且前测错误 | basic |
| 无画像盲区但前测错误 | applied |
| 前测正确且证据充分 | advanced 验证任务或标记候选掌握 |
| 未测试且无画像证据 | applied 探测任务，不允许直接跳过 |

验收标准：10 个知识点均有可解释的状态和难度来源；不同错题组合必须产生不同学习路径；第二域只需替换领域题和知识点配置，不修改诊断算法。

### 阶段 3：追问动态选靶与 T17 内容差异增强

目标：减少模板化，让问题真正围绕学员暴露的缺失证据和误区变化。

实施内容：

1. 将前测错项类型正式加入 Follow-up Agent 的候选输入；
2. 候选问题按“未结清纠错票据、缺失证据字段、未覆盖关系点、历史去重”确定性排序；
3. Review 批准后才允许关系点计入覆盖；
4. T17 保存并排除上一轮 `chunk_id`、任务模板 ID 和问题规范化签名；
5. basic 无法继续降阶时，必须换证据块、解释角度或任务模板；
6. 无替代资源时明确记录“资源不足”，第二次失败走 `deferred`，不伪造内容差异。

验收标准：相同历史前缀和固定桩可复算；不同误区产生不同首个策略分叉；同一补学周期不重复使用完全相同的资源—任务—追问题组合。

### 阶段 4：实操审计与前端反馈完善

目标：让初学者看得懂系统为何阻止、为何继续、为何降阶。

实施内容：

1. 补充 `sql_failure_reason`、`sql_failure_history` 和任务签名；
2. 第 3～4 次提示从当前任务授权字段生成，不泄漏完整答案；
3. 将“不会”展示为教学事件，并给出从结果表字段入手的第一步提示；
4. 无关回答和题目复述必须显示明确原因，不能只表现为按钮无反应；
5. 修复历史轮次标签数字方向；
6. 训练报告展示 deferred、补学次数、初始/最终难度和未结清知识点。

验收标准：失败提示与后台原因一致；前端不出现 R/T/S 编号和内部工程术语；窄屏与常规分辨率均通过视觉回归。

### 阶段 5：组合门禁和正式评测

执行顺序：

1. 阶段 1 单项非 live 全量回归、第二域回归、消融；
2. 阶段 2 单项回归与逐知识点路径消融；
3. 阶段 3 单项回归与创新 B 消融；
4. 阶段 4 前后端组合回归；
5. 创新 A+B 组合门禁；
6. 代码冻结后再运行正式 50×2、三个指标和 Docker 镜像验证。

正式报告需要分开表述：

- 50×2 只用于说明最终组合版本的幻觉率、适配率和知识覆盖率不回退；
- 第二域迁移由独立固定桩完整交互、Agent/关系函数测试和 domain-swap 回归证明；
- 不使用 50×2 结果替代第二域迁移证据。

## 五、实施顺序与风险等级

| 顺序 | 修改项 | 风险 | 预计影响范围 |
|---|---|---|---|
| 1 | 下一知识点独立定档 | 低～中 | 诊断结果、`continue_learning()`、路径展示 |
| 2 | 纠错票据与升档门禁 | 中 | 追问状态、评价文案、报告 |
| 3 | 前测覆盖与逐知识点诊断 | 高 | 前测题库、诊断 Agent、路径生成、前端 |
| 4 | 动态选靶与 T17 内容签名 | 中～高 | Follow-up Agent、知识 Agent、资源缓存 |
| 5 | SQL 审计和前端反馈 | 低～中 | Session 字段、实操界面、报告 |
| 6 | 组合门禁和正式评测 | 高 | 全系统，不再修改业务代码 |

不建议同时修改阶段 1～3 中共享的 `interactive_session.py`。每个阶段应按“失败测试 → 最小实现 → 非 live 全量回归 → 第二域回归 → 消融 → 单独提交”的顺序进行。

## 七、下一步建议

下一次开发建议只实施“阶段 1”：

1. 先修复知识点难度继承；
2. 再建立证据绑定的历史纠错票据；
3. 完成阶段 1 的固定桩、非 live 全量、第二域回归和消融后提交；
4. 审核通过后，才进入前测覆盖与逐知识点诊断重构。

该顺序优先解决明确错误，改动范围可控，也能保护当前多 Agent 协同、Review、创新 A/B、三指标和第二域迁移能力。
