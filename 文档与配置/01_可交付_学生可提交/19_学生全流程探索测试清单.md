# 学生全流程探索测试清单

本文用于组织学生对创新 A+B 版本进行探索性测试，目标是发现实现错误、偶发故障、状态不同步和不符合学员直觉的交互，而不是重复证明既有正式评测结论。

## 1. 测试范围与版本

- 推荐入口：`http://127.0.0.1:18082/`
- 旧版 `18080` 与协同对照版 `18081` 继续保留，不要覆盖或删除。
- 测试前执行 `git rev-parse --short HEAD`，把提交号记录在报告中。
- 使用个人获授权的模型 Key 和只读数据库账号，不得把 `.env`、Key、密码或含敏感信息的截图提交到 Git。
- 不执行 `docker compose down -v`，不删除已有数据库卷。

本轮学生测试不要求重新执行正式 50×2。正式 50×2 由指定负责人在最终代码冻结后统一执行；第二域证据继续使用独立固定桩和 domain-swap 回归，不能表述为“两个领域各跑 50 例”。

## 2. 缺陷严重级别

| 级别 | 判定示例 |
|---|---|
| S0 | 数据被写入或删除、跨学员会话串联、密钥泄漏、未授权查询成功 |
| S1 | 主流程无法继续、刷新或短暂断网后会话丢失、错误内容进入学员界面 |
| S2 | Agent 状态与实际动作不一致、证据或审核结论错误、偶发重复提交 |
| S3 | 文案、布局、动画、兼容性或轻微性能问题 |

发现 S0 时立即停止相关测试并通知负责人，不要继续扩大操作范围。

## 3. 每台环境先做的冒烟检查

1. 确认 `18080`、`18081`、`18082` 的用途没有混淆。
2. 打开 `18082`，页面标题应为“船厂数字化岗位培训”。
3. 在“会话回放”中切换至少两条回放，播放、暂停、单步和速度切换均应可用。
4. 切换“学员模式/协同视图”，页面不得白屏、横向溢出或出现破图。
5. 打开浏览器开发者工具，记录 Console 红色错误和 Network 失败请求。
6. 执行：

```powershell
docker compose `
  --env-file .\Docker镜像\.env `
  --file .\Docker镜像\docker-compose.innovation-ab.yml `
  ps
```

前后端均应为 `healthy`。若不健康，先保存 `docker compose ... logs --tail 200`，不要直接删除容器或数据卷。

## 4. 三种画像的完整主流程

三位学生分别承担一种画像，至少完整执行一次：

1. 选择岗位画像。
2. 完成 5 道岗前测评。
3. 检查诊断盲区、课程难度和微课内容是否与作答差异相符。
4. 打开岗位微课并领取实操任务。
5. 按当前任务要求编写只读 SQL，不要直接复制其他画像的答案。
6. 提交 SQL，检查查询结果、审核结论和学员侧解释是否一致。
7. 故意给出一次证据不足或理解有偏差的判断，走完 2～4 轮理解核对。
8. 完成培养目标后进入下一知识点，确认新旧知识点、任务、Agent 状态没有串联。
9. 导出会话记录，再导入回放，检查主要步骤和结果能否复现。

每一步至少记录：实际输入、预期结果、实际结果、耗时体感、是否可继续、会话/Trace 标识。

### 4.1 个性化必须重点观察

- 三种画像的盲区、难度、讲义重点和任务是否真的不同。
- 相同错误是否因为画像和历史不同而得到合理不同的后续动作。
- 系统是否只是替换岗位名称，实际内容却基本相同。
- 下一知识点是否来自当前诊断和已完成历史，而不是固定顺序。

## 5. Agent 协同与创新 A+B

在“协同视图”中完整观察至少一轮内容生成和审核：

- 工作中的 Agent 应有明确动效；待机、协作、审核、完成状态应可区分。
- 领域知识、实操任务和数据验证的状态顺序应与主流程一致。
- 专业审核组中的审核分支应显示各自的执行、汇聚和最终裁决状态。
- 分支仍在工作时，父级审核 Agent 不应提前显示“完成”。
- 进入下一知识点后，不应残留上一知识点的并行证据或工作状态。
- 学员侧不得出现 `R-02`、`R-03`、状态枚举、内部提示词、错误堆栈等工程术语。

创新 A 重点检查：只有允许反馈的争议点进入选择性辩护/受控反馈；硬规则命中时必须安全结束，不能靠辩护绕过。

创新 B 重点检查：关系追问应与本轮真实暴露且审核通过的误区相关；不得重复选择已经覆盖、没有新增支持的关系点；证据不足时应安全退化。

## 6. 本轮必须验证的轮询恢复修复

### 6.1 临时断网恢复

1. 进入实操并停留在岗前测评、SQL 或理解核对页面。
2. 在浏览器开发者工具的 Network 面板中切换为 `Offline`，保持约 2～3 秒，使至少一次轮询失败。
3. 页面可以显示“服务暂时不可用”，但当前会话、已填内容和当前步骤不得消失。
4. 恢复 `Online`，等待 1～2 个轮询周期。
5. 错误提示应自动消失，用户应能从原步骤继续。

每种浏览器至少重复 3 次。如果任意一次回到岗位选择页，按 S1 报告。

### 6.2 刷新与重新打开

- 正常步骤按 `F5`，应恢复同一会话。
- 关闭标签页后重新打开 `18082`，应恢复未完成会话。
- 恢复过程中发生一次短暂网络失败，网络恢复后仍应自动重试。
- 可选技术测试：将 Session Storage 中的 `ref-interactive-session` 改成不存在的测试值并刷新。服务端明确返回 404 后，系统应提示上次训练已失效并回到岗位选择。

## 7. SQL 安全与异常输入

在当前任务允许的字段和范围内，分别验证：

| 场景 | 预期结果 |
|---|---|
| 合法聚合 `SELECT` | 执行并返回不超过 200 行的结果 |
| 查询未授权字段或扩大船号/月份范围 | 被模板权限或审核阻断 |
| `INSERT`、`UPDATE`、`DELETE`、`DROP` | 必须阻断，数据库不得变化 |
| 多语句、注释绕过、危险函数 | 必须阻断 |
| 空 SQL、语法错误、超长输入 | 给出学员可理解的提示，不显示堆栈 |
| 连续快速点击提交 | 最多形成一次有效动作，不应生成重复结果 |

负向测试只在系统输入框中提交，不得绕过系统直接对数据库执行写语句。

## 8. 会话隔离与并发边界

1. 普通窗口和无痕窗口分别选择不同画像。
2. 两个会话交替完成测评、课程和 SQL 操作。
3. 检查画像、题目、Agent 状态、查询结果和下一知识点是否互相串联。
4. 在同一会话中快速双击“继续”“提交判断”等按钮，检查是否重复推进。
5. 一台机器最多做 2～3 个并行会话，不进行压力攻击或批量模型调用。

出现跨会话数据或状态混合时按 S0 报告。

## 9. 第二域与固定桩回归

第二域当前主要通过配置和固定桩证明迁移不回退，不要求在主域 UI 中伪造第二域效果：

```powershell
Set-Location source_package
.\.venv\Scripts\python.exe -m pytest eval `
  -k "second_domain or domain_swap or d3_transferability" -q
```

重点检查：

- 第二域 schema、意图、证据关系和安全范围均来自自己的配置包。
- 第二域不得出现主域船舶工序、主域误区编号或主域表字段。
- 不支持的多节点关系应安全退化，不得为了制造收益临时增加关系。

## 10. 自动化回归

后端非 live 全量：

```powershell
Set-Location source_package
.\.venv\Scripts\python.exe -m pytest eval -k "not live" -q
```

创新 A/B 定向测试：

```powershell
.\.venv\Scripts\python.exe -m pytest `
  eval/test_innovation_a_selective_rebuttal.py `
  eval/test_innovation_a_ablation.py `
  eval/test_innovation_b_marginal_routing.py `
  eval/test_innovation_b_ablation.py `
  eval/test_innovation_b_second_domain_interaction.py -q
```

前端：

```powershell
Set-Location source_package\frontend
npm ci
npm test -- --run
npm exec vue-tsc -- -b --pretty false
npm run build
```

当前轮询恢复修复的关键断言位于 `LivePractice.spec.ts` 和 `interactiveApi.spec.ts`。测试不得删除或放宽这些断言来换取通过。

## 11. 浏览器与界面组合

至少覆盖：

- Chrome 与 Edge 最新稳定版。
- 1920×1080、1366×768。
- Windows 缩放 100%、125%、150%。
- 浏览器减少动态效果设置开启和关闭。
- 外部浏览器与应用内浏览器各一次。

重点观察协同舱是否截断、重叠，滚动区域是否互相抢焦点，动画是否只在某一种浏览器中工作。

## 12. 已知限制，不作为重复新缺陷

- `18080`、`18081` 与 `18082` 本来就是不同版本，画面和功能不要求一致。
- 静态回放没有真实 SSE 运行事件，不能替代实时实操中的 Agent 并行证据。
- 正式 50×2 曾有安全拒绝和前置检查耗尽案例；新出现的不同失败仍应报告。
- 当前自动适配率不是已完成的真人教学有效性实验，不要在测试报告中扩大结论。

如果已知限制的频率、影响或表现明显恶化，仍按回归缺陷报告。
