# 8-4 问题 5、7、8、9、6 修复与验证报告

## 一、修复范围与结论

本轮按 **5 → 7 → 8 → 9 → 6** 的顺序修复《8-4 测试相关问题及优化》中的五项确认缺陷，并为每项补充了自动化验证；问题 5、6、9 另外使用本地 `18082` 页面完成了真实交互复验。

| 编号 | 问题 | 修复结论 |
|---|---|---|
| 5 | 错误回答导致追问生成/审核异常后，整场学习被安全终止 | 已修复：保留上一道已审核追问，允许学员继续作答；未审核候选不向学员展示 |
| 7 | SQL 降阶补学后沿用上一阶段失败次数 | 已修复：T17 补学开始时清零 SQL 失败计数和提示状态 |

| 9 | SQL 成功后页面跳回微课 | 已修复：SQL 结果和理解核对在路径更新阶段继续停留于实操工作台 |

## 二、逐项修复说明

### 2.1 问题 5：错误回答不再导致整场会话退出

**根因**

错误答案进入定向追问后，如果新追问在 Review 重试耗尽、事务被中断或关系完整性校验失败，旧逻辑会把局部内容生成失败升级为整个会话的安全结束。同时，前端按“最后一条题目消息”展示内容，可能把已经被 Review 驳回的候选追问题显示给学员。

**修改**

1. 对 `ReviewFlowTerminal`、`ReviewFlowInterrupted` 和 `RelationIntegrityError` 增加局部恢复：
   - 保留上一道已通过审核的追问题、轮次和答题历史；
   - 标记本次需要重试，但不结束学习会话；
   - 不提交未通过审核的关系覆盖点；
   - 给学员显示“保留上一题、可重新作答”的解释。
2. 学员资源面板与协同审计轨迹分离：
   - 协同视图继续保留被驳回候选，便于审计 Agent 行为；
   - 学员视图只显示当前交互绑定的已批准题目，或 Review 明确批准的最后一道题目；
   - 路径更新后也不会重新泄漏被驳回候选。

**验证**

- 后端参数化测试覆盖 Review 耗尽、事务中断、关系校验失败三类异常，均验证：会话未结束、上一道题保持不变、覆盖点不被污染。
- 创新 B 的关系路由测试验证：无效关系候选不会写入覆盖集合，也不会增加无效模型调用。
- 前端新增测试验证：学员指南在追问中和进入下一阶段后都不展示被驳回候选。
- 浏览器手动复验：连续提交不完整答案后页面提示“保留上一道已审核题目”，主追问题与指南题目保持一致，会话未退出。

### 2.2 问题 7：降阶补学后 SQL 失败次数重置

**根因**

T17 只更新学习阶段和难度，没有清理 `sql_failure_count` 与旧的 SQL 提示，因此学员进入新的补学阶段后仍继承旧阶段的失败次数。

**修改**

每次真正执行 T17 补学时统一：

- `sql_failure_count = 0`；
- `sql_support = None`。

新难度/新资源阶段由第 1 次尝试重新计数；同一阶段内部仍保留原有分级提示和降阶阈值。

**验证**

- 集成测试连续制造 SQL 失败并触发 T17，断言补学状态已建立、失败计数归零、旧提示被清除。
- 同一测试同时确认原分级序列仍为“自主纠错 → 结构化提示 → 半填充模板 → 降阶”，未削弱原引导逻辑。

### 2.3 问题 8：补学微课生成失败时提供受审兜底

**根因**

补学阶段仍完全依赖一次新的 LLM 微课生成；模型调用失败时，即使已有通过证据绑定的知识块，流程也只能进入系统错误收尾。

**修改**

新增“已批准证据投影”兜底，但边界严格限定为：

- 仅限 **T17 补学上下文**；
- 仅捕获明确的 `LLMCallError`，不吞掉代码错误、配置错误或 Review 错误；
- 只从本轮已检索、已绑定的知识块句子生成基础讲义；
- 生成后必须重新通过硬规则检查、R-04 预检和原有完整 Review 流程；
- 兜底内容仍不能通过审核时，继续按安全失败处理。

因此，这不是绕过大模型/审核的静态答案，而是模型不可用时对已有批准证据的确定性教学投影。

**验证**

- 故障注入测试强制补学微课发生 `LLMCallError`；
- 验证系统返回可继续学习的讲义，而不是结束会话；
- 验证讲义标记为 `deterministic-evidence-projection`，声明、证据引用和 Review 通过记录完整存在。

### 2.4 问题 9：SQL 结果保持在实操工作台

**根因**

SQL 成功后短暂进入 `S9_PATH_UPDATE + awaiting=advance`。原布局判断没有识别“已有 SQL 结果且等待继续”的组合，于是按微课资源存在回退到微课布局。

**修改**

当状态为 `S9_PATH_UPDATE`、已有 SQL 结果且等待下一步时，继续使用实操布局。查询结果、理解核对和“查看下一步训练”在同一工作台呈现。

**验证**

- 前端组件测试构造该状态，断言工作台使用 `is-practice-layout`，实操组件保持显示。
- 浏览器手动提交真实标准 SQL，结果返回 WSB `0.6218`、WSA `0.6253`；随后进入理解核对，查询表格始终保留在实操区，没有跳回微课。

### 2.5 问题 6：完成率极值题采用稳定的双向证据门禁

**根因**

旧逻辑只在“模型判错、确定性规则判对”时纠正模型的假阴性；如果模型在后续轮次把缺少数值的回答判为掌握，确定性规则不会反向阻止，导致相同答案出现先拒后通过。

**修改**

对“完成率最低/最高、排序或比较”这类有两行以上查询证据的题，增加双向门禁：

- 回答必须命中查询结果中的实体字段；
- 回答必须命中该实体对应的精确数值；
- 实体和值不同时满足时，即使模型返回 `mastered`，也只能判为未掌握；
- 实体和值都匹配时，确定性规则仍可纠正模型的假阴性。

门禁只作用于可由结构化查询结果确定复算的极值题，不扩展到概念解释题，避免把语义理解退化成关键词匹配。

**验证**

- 单元测试验证：模型声称“掌握”但回答缺少已查询数值时，最终仍为未掌握。
- 回归测试验证：带有正确实体和值的回答可以通过。
- 浏览器手动复验：
  1. 第 1 轮输入“WSB完成率最低”——未掌握；
  2. 第 2 轮再次输入相同缺数值答案——仍未掌握，不会因轮次变化放宽；
  3. 输入“WSB责任单元完成率最低，为0.6218”——通过，并明确反馈“与查询结果中的最低值一致”。

## 四、对赛题架构与创新点的保护

本轮修改属于鲁棒性加固，没有把系统退化为固定脚本：

1. **未修改 21 条状态转移定义**，T17、T16、T19 等状态语义保持不变。
2. **未修改三指标算法及正式评测口径**。
3. **未放宽 R-01～R-05**：问题 5 保留审核失败事实，问题 8 的兜底讲义仍经过硬规则、R-04 与完整 Review。
4. **保留创新 A 的选择性辩护/受控反馈闭环**：局部审核失败只回滚本次候选，不破坏整个学习事务。
5. **保留创新 B 的误区关系选靶**：未批准关系不写入覆盖集合，关系覆盖仍以 Review 通过为前提。
6. **强化赛题第 3 点“动态反馈”**：错误不会直接终止；判定稳定；降阶后形成新的尝试阶段。
7. **保持赛题第 5 点“合规与伦理”**：SQL 只读沙箱、证据绑定、审计轨迹和学员可见内容隔离均未削弱。
8. **不虚增第 6 点“跨域迁移”证据**：本轮是领域无关的流程鲁棒性修复，但第二域是否不回退仍需独立 domain-swap 回归证明。
