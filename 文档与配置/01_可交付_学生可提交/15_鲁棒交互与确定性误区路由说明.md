# 鲁棒交互与确定性误区路由说明

## 1. 目标

本增强解决两个问题：一是内部生成或状态转换异常不能让学员卡在半完成会话；二是重复误区的下一轮目标不能由模型自由选择。

## 2. 确定性误区路由

系统从已审核知识块的 `common_mistakes` 构造对称关系图，并按以下条件选择下一目标：

1. 只保留当前领域声明的误区编号。
2. 只保留与当前岗位责任范围相交的关系证据。
3. 排除本次训练已经探查的目标。
4. 先按知识点支持数、再按知识块支持数排序；同权重时按领域配置顺序稳定排序。
5. 第一次识别某误区时继续确认该误区；重复未掌握时才转向首个合格关联目标。
6. 模型返回的下一目标与确定性结果不一致时安全拒绝，不展示该问题。

审计记录分别保存 `diagnosed_misconception` 和 `next_target_misconception`。专业审核要求重生成问题时，这两个字段不得变化。

## 3. 异常安全结束

产物生成、审核闭环或跟进终态转换出现内部异常时，系统会：

- 将会话置为 `awaiting=done`、`outcome=system_error`；
- 清除未完成的学习动作；
- 保留最后一个已批准产物；
- 返回面向学员的安全结束提示；
- 对重复“下一步”和相同 `client_turn_id` 的重复提交返回同一结果；
- HTTP 层返回 409 和公开错误类别，不返回堆栈、内部状态或规则细节。

## 4. 手工验证

正常流程中，连续两次围绕同一误区提交仍需支持的回答。第一轮追问仍围绕原误区；第二次重复未掌握后，审计消息中的下一目标应由关系图确定。当前生产域中，M-01 在“计划量与实际量口径”责任范围内优先关联 M-04。

自动验证：

```powershell
Set-Location source_package
.\.venv\Scripts\python.exe -m pytest -q `
  eval/test_misconception_relations.py `
  eval/test_follow_up_agent.py `
  eval/test_interactive_session.py `
  eval/test_p5_interactive_follow_up.py
```

关系图、跨域隔离、目标不一致拒绝、终态异常、幂等请求和 HTTP 错误脱敏都包含独立断言。
