# 教学闭环鲁棒性升级与架构守护说明

## 一、升级目标

本次升级解决追问与实操环节中“答对当前一题就升档、T17 原样重学、无效回答误判、重复追问、SQL 多次失败缺少递进帮助”等问题。

升级不是重新设计多智能体架构，而是在原有状态机、Review 质量门、证据绑定和创新 A/B 机制之外增加确定性的教学闭环约束。

## 二、架构守护边界

本次保持以下部分不变：

- 21 条正式状态转移的编号、方向和审核语义不变；
- 领域知识、实操任务、数据验证、专业审核等 Agent 的职责边界不变；
- 创新 A“选择性辩护—再审核—安全收尾”不变；
- 创新 B“误区关系候选—边际覆盖—Review 批准后计入覆盖”不变；
- 幻觉率、适配率、知识覆盖率的计算算法不变；
- 数据库只读白名单、安全规则 S-01～S-09 与审核规则 R-01～R-05 不放宽；
- 第二域通过领域包、关系函数和相同交互接口接入的方式不变。

## 四、与赛题要求的关系

### 4.1 赛题要求 3：智能决策与反馈

- 学员回答不再只看“当前一题”，而是维护可审计的历史错误状态；
- 系统能依据连续错误选择继续核对、降阶、换内容或延后补学；
- SQL 提示由失败次数自动分级；
- 训练状态对前端公开 `remediation_status` 与 `sql_support`，可用于画像、路径和过程展示。

### 4.2 赛题要求 5：数据合规与伦理

- SQL 仍只通过原有只读白名单和 S-01～S-09；
- 分级提示只暴露任务契约中已授权的字段，不泄漏标准答案、内部提示词或数据库凭据；
- 无效回答门禁采用学习语言反馈，不把未知误判为掌握；
- 所有契约修订和 T17 转移继续写入审计轨迹。

### 4.3 赛题要求 6：行业与第二域延伸

- 降阶、去重、历史纠错和 SQL 分级均不写死船舶领域答案；
- 结构化提示读取当前任务的 `query_authority`；
- 第二域仍使用相同 Agent 接口、关系函数和 Review 机制。

## 五、学术创新守护

本次升级没有把 SELENE、AToM 或 MAAT 的算法直接搬入系统：

- 创新 A 仍由审核规则性质、事务内辩护历史和固定预算决定是否启动辩护；
- 创新 B 仍由确定性候选集合、责任范围、证据绑定和边际关系覆盖决定下一误区目标；
- 新增的“历史错误纠正门禁”是两项创新的教学状态约束，不替代 Review，也不把单次 LLM 置信度当作完成依据；
- 新增的 T17 契约修订让动态难度真正落地，同时保持内容寻址、可审计和 fail-closed。

## 六、验证结果

- 后端非 live 全量回归：`1162 passed, 11 deselected`；
- 创新 A/B、消融接口与第二域专项：`53 passed`；
- 前端组件回归：`315 passed`；
- 前端生产构建：通过 `vue-tsc -b && vite build`。

## 七、边界说明

- 明显无关文本由确定性规则提前拦截，复杂语义无关仍交给原 Follow-up Agent 与 Review，避免误伤自然语言正确答案；
- basic 档若检索不到不同知识块，会保留原证据范围但改变补学上下文；第二次仍失败即 deferred，保证不会无限循环；
- `deferred` 表示本轮未掌握，不等于完成或通过；训练报告会明确列出后续补学项。
